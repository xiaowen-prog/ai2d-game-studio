# 2-4 场景｜让人物进入自己的游戏世界

**AI 制作背景，把已确认人物和动作放进去；用户可以描述修改、确认和恢复。完成后停在场景。**

## 范围与使用

1. 已确认动作的旧项目显示“开始制作场景”；打开项目不会自动调用模型。
2. 新人物动作确认后可继续场景。AI 制作一张适合横版／俯视视角的场景底图，放入原人物和动作，显示真实 Godot 预览及操作说明。
3. 输入“竹林改成雪山，人物保持不变”，AI 更新背景；人物图片、动作图集和动画资源保持原样。仅调亮度等效果可复用图像。
4. 确认场景只保存，停在 2-4。可以恢复旧版；返回人物或方向修改须先说明影响，后续场景重新确认。

只做画面与空间组合。复用已有动作便于检查人物在场景中的比例，不新增敌人、碰撞规则、地图关卡、胜负、完整玩法或导出交付界面。

## 实现

延续 Electron／React／TypeScript、Codex App Server、Godot 4、已有文件存档及版本机制。新增场景提示词、场景清单检查与实际运行检查，扩展原动作检查器验证真实背景绑定、人物可见及动作响应；不新建另一套引擎，不新增依赖。

`.noobi/scene-preview.json` 记录 schemaVersion、当前 taskId、方向类型、已确认人物版本／快照、背景路径和场景节点、人物节点。宿主核对私有生图证明、人物与动作文件摘要，运行原导入／脚本检查／网页导出，检查实际生产场景后再交 AI 审查。旧报告归档，当前结果绑定当前任务和文件摘要。

沿用 creation IPC、统一错误结构、异步任务状态、原子写入与确认点。增加已确认动作继续场景的动作，校验版本和前置确认；任务结束仍需用户确认。候选图片确认不能绕过动作。场景确认后不解锁核心试玩。失败保留上版，不自动重画。

模型及配置沿用已有设置，私有凭据不进入工程或证据。场景只开放图片规划／生成／登记工具，不开放音频、3D 或新服务。预览内短英文按钮沿用已验证做法，外层说明保持中文。

## 验收

| 维度 | 标准 |
| --- | --- |
| AI 场景 | 横版、俯视各一份真实 AI 场景；视角适配，人物大小合理且可辨认 |
| 实际接入 | 背景位于真实 Godot 场景，非单独概念图；按键仍能触发原动作 |
| 人物继承 | 原人物、另一候选、动作图集、动画资源及动作清单摘要保持一致 |
| 持续修改 | 至少一次真实背景替换，显示实际新背景，人物动作不变 |
| 审查与失败 | 错版本、缺生成证明、背景未接入、人物隐藏或资源被改均拦截；旧版仍可查看 |
| 交互与恢复 | 开始、修改、确认、恢复、重开均可用；桌面和窄窗口实看；确认停在场景 |

先跑离线单元和实际 Godot 检查，再复用 2-3 的两个人物做真实验证。计划两份初始背景加一次背景修改，共最多 3 次图片、9 次文字调用；各任务自动修复为 0。失败先查原因，复用已有产物，不盲目重画。沿用现有订阅，不新增付费 API。实际调用量、失败及恢复由脚本留存。

本节点测试不等于验证所有题材。完整玩法在后续节点完成。按照 Skill 交证据、运行自检、等待用户验收，不自动进入下一节点。

## 实测发现与修复

真实“竹林改雪地”首次在二次宿主检查时失败：素材核对会更新旧工单的更新时间，导致旧竹林误被当作本轮新增工单。改为依据当前引用路径和工单创建时间选择本轮范围；旧素材仍保留，但替换后不要求继续出现在画面。新工单、当前引用素材仍严格检查，完整游戏检查不放宽。新增回归用例覆盖连续两次核对。

为避免重画，修复复验使用上一轮已生成、登记并接入的雪地草稿：测试准备将失败草稿复制到隔离工作副本，再走正式制作与审查流程。这是诊断恢复，不宣称普通用户重试必然复用失败草稿。额外最多 3 次现有订阅文字调用，新增图片 0。最终总量以自动汇总为准。
