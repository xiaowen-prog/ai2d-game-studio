# 2-6 俯视核心试玩

**让 AI 把已确认的人物和场景做成能移动、攻击的小样，并能按一句话把剑气改成碰墙反弹一次。**

## 范围与使用

依据已确认技术适配声明第 7 节。复用俯视人物、动作、场景及前五个节点；不增加新类型，不做波次、成长、整局胜负、音效或交付节点。横版核心试玩继续保留。

打开已确认俯视场景，点击“开始核心试玩”，AI 编写实际 Godot 玩法代码。用户用 WASD 移动、J 朝最近移动方向发射剑气、R 重来。小样包含实体墙和三个可击中的练习目标，命中有反馈与计数。初版剑气碰墙消失；输入“剑气碰墙反弹一次，其他保持不变”后，AI 修改碰撞行为，第二次撞墙消失。

已确认人物、衣服、发型、动作图集、动画资源和背景均保持原文件。只允许简单形状表示墙、练习目标与剑气，不重新生图。确认仅保存本节点，不进入完整游戏；恢复已有版本不调用模型。

## 技术与复用

继续使用 Noobi 的 Electron/React、Codex 规划/制作/审查、Godot 导入/脚本检查/Web 导出、本地版本快照和私有素材证明。没有新依赖、引擎或付费接口。

新增俯视玩法提示词、清单解析和引擎对象检查。`CreationArtifact.playable` 按 genre 区分横版 maxJumps 与俯视 maxBounces，旧横版数据保持兼容。俯视清单 `.noobi/topdown-preview.json` 记录当前 taskId、已确认场景版本/快照、人物/墙/练习目标/剑气容器/HUD 路径及剑气场景资源、反弹次数 0 或 1。错误清单、错版本、资源变更阻断候选替换，保留上一版。

沿用 creation.get/act/preview、任务事件、确认、修改、停止、失败和恢复机制。界面按方向显示不同操作及示例；主进程同时限制开放到核心试玩。生成线程的修复次数仍为 0，模型和账户走现有配置。

## 验收交接

按用户 2026-11-06 最新要求，**试玩验收由用户进行**。助手完成开发和启动所需构建，准备可操作入口、验收标准与指标；不运行额外自动试玩或反复模型验收，不把宿主结构检查当成用户试玩通过。产品生成时原有的素材保护、工程导出和审查仍保留；本节点新增的宿主检查只核对实际引擎对象与资源绑定，不宣称反弹效果已通过人工验收。

| 操作 | 通过指标 |
| --- | --- |
| WASD 移动 | 四方向可移动，斜走不明显加速；遇墙不能穿过 |
| J 攻击 | 朝最近移动方向发射，角色播放原攻击动作，目标受击后反馈，计数只加一次 |
| 初版对墙发射 | 碰墙消失，不穿墙、不反弹 |
| 输入“剑气碰墙反弹一次，其他保持不变” | AI 输出新版本，第一次撞墙改变方向，第二次消失；目标命中仍有效 |
| 对比修改前后 | 人物、背景、地图、目标数量和移动速度保持 |
| R 重来 | 人物回原位、目标恢复、计数归零、场上剑气清除 |
| 确认、恢复、重开 | 同一版本可恢复；完整游戏没有自动启动 |

## 制作中发现的问题与修正

首次真实生成被审查拦下，没有交付为成功：攻击锁定期间方向输入仍改变瞄准；审查规则又把缺少自动剑气试玩记录当成失败。

已补充“实际移动后才更新瞄准，攻击锁定时保持原方向”的制作规则。仅对俯视核心试玩明确区分审查边界：实际代码缺陷、引擎报错、素材变化仍然阻断；完整操作效果交用户验收，不要求助手另跑自动试玩，不因缺少人工体验记录直接判失败。原横版、人物、场景和完整游戏的检查范围不变。
