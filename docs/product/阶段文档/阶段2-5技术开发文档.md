# 2-5 横版核心试玩

**把已确认的人物、动作和场景变成能跑跳、收集、越过障碍、到达目标的小样；AI 可以继续加入落地恢复的二段跳。**

## 范围和使用

依据技术适配声明第 7 节及 PRD A05/A06。本次只开放横版核心试玩；俯视仍停在场景，2-6 单独验收。完整小局、敌人、胜负结算、音效、发布均留在后续节点。R 重来仅用于反复体验小样。

旧项目打开不自动生成。已确认横版场景显示“开始核心试玩”；AI 制作完成后出现真实游戏窗口、操作与目标说明。用户试玩后可以输入“加入落地恢复的二段跳，其他不变”，再试玩并确认。确认只保存，停在核心试玩；历史恢复不调用模型。

## 技术与复用

继续复用 Noobi.ai 的 Electron/React、Codex 规划/制作/审查、Godot 4、现有动作资源、素材证明、版本快照和受控桌面接口。不新增依赖或第二套引擎。

AI 负责实际游戏代码；平台只提供交付约束与验收，不把业务做成固定参数模板。角色真实使用 CharacterBody2D、碰撞地面和障碍；收集、目标与反馈必须由实际接触触发。场景背景、人物图、动作图集及 SpriteFrames 保持已确认的文件摘要；继承动作／场景清单不改。新玩法清单记录本轮 taskId、场景版本与快照、实际物理节点和跳跃次数。

新增 creationPlatformer 的提示词与清单校验、platformerInspection 的原生引擎检查；原生成器接入检查，保留已有导入、脚本检查、网页导出与动作播放核验。素材范围沿用 2-4 的当前引用和创建时间规则，防止旧背景记录干扰。playable 成果增加 manifest、genre、maxJumps 字段；旧数据无需迁移。

## 状态与接口

沿用 creation.get/act/preview、异步任务事件与统一错误结构。continue 扩展支持“已确认横版场景→核心试玩”，旧版本、未确认或俯视请求由主进程拒绝；重复操作不重复生成。生成、确认、修改、停止、失败和恢复沿用原子存储。失败保留已有成果；不自动重试。

界面与主进程共用按游戏方向计算的开放范围。确认核心试玩不启动完整游戏；俯视场景确认仍只保存。返回修改前面成果继续提示影响。

## 验收

| 维度 | 标准 |
| --- | --- |
| 真实 AI | 复用 2-4 横版样例，AI 实际制作核心试玩，再实际加入二段跳 |
| 原素材 | 背景、两候选、图集、动画资源、动作／场景清单摘要不变 |
| 操作 | A/D 移动、空格跳跃；碰撞能阻挡且能跳过；接触收集计数一次；收集齐才能在目标处完成 |
| 二段跳 | 第一次正常起跳，空中第二次出现实际向上速度，第三次无新冲量；落地恢复；重来恢复 |
| 完整关键行为 | 从出生点只使用真实按键，收集全部并到达目标，不靠修改计数或传送完成 |
| 持续修改 | 玩法实际生效；无关动作、美术和规则保留；修改后需要重新确认 |
| 保存与边界 | 确认、旧版本恢复、新进程重开一致；俯视与完整小局未开启 |
| 失败与界面 | 错版本、改图、缺实际物理行为被拦截；旧版保留；桌面和窄窗口实看 |

原生检查分为独立规则测试和从出生点的真实键盘路线：独立规则测试允许宿主摆放人物来触发碰撞／收集／目标，路线测试不得传送或改计数。另用真实网页键盘体验和截图验证，不能以清单或视频代替。

先用工程用例验证检查器，再用真实 AI 跑生成与修改。拟使用现有订阅 6 次文字、0 次图片，自动修复 0；无新付费 API。若失败，先诊断再修复，复用已生成素材，所有失败与实际用量由脚本记录。本节点无新的待确认决策。

完成后交验收报告、截图、照着做清单、是否表及自动冒烟记录；运行 kit.sh 自检。用户验收前不进入 2-6。
