# 2-9 跨阶段修改与整体恢复

**完整游戏做好后，可以只改衣服或背景，保留玩法；不满意时恢复整套旧版本。**

本次用户“继续开发”授权进入 2-9，不据此补记 2-8 效果验收通过。继续使用开发 Skill，已核对规则卡及通用手册第二、三部分；底线无冲突。按用户“助手开发、用户验收”的要求，不执行自动测试、模型冒烟、试玩或最终 Skill 自检。通过流程管家校正到 2-9 并领取任务。

## 首版交互

在已确认的完整游戏中选择“人物外观”或“场景背景”，输入修改描述。先展示影响：人物会同步原图、动作图集与游戏；背景会同步场景和游戏；玩法、碰撞、升级、倒计时、音效保持。确认影响后才调用 AI。

AI 输出新图片，宿主将修改接入原工程，展示修改前后图片与真实游戏预览。涉及的阶段统一标为待确认；用户看完后确认整套修改。不满意可恢复“外观修改前整套版本”，图片、玩法和确认状态一起恢复；较新版本保留。

此入口不换角色、不换动作、不改变尺寸和姿态、不修改玩法或游戏类型。人物外观使用原图与原动作图集的局部 AI 编辑，衣服以外区域保留原像素。改变玩法仍用原修改入口；改变早期方向仍展示后续需要更新的阶段，不把过期成果当成最新确认版。

## 实现与复用

- 复用现有 Codex 图片编辑、宿主生成来源证明、局部像素合成、Godot 导出、版本库与原子工作流写入。
- 新增外观修改任务和影响信息。AI 仅输出新图和修改区域，宿主核对原工程文件未被改动，再接入素材。玩法代码、场景结构、动作分格和播放速度保持原文件。
- 任务指令要求人物修改两张图（原图、动作图集），背景一张；宿主只接受对应数量的修改项。仅使用现有订阅，不启用付费图片 API、音乐 API 或自动重画。
- 在各阶段原快照上应用同样的图片替换，重建对应预览，并串联新的人物、场景、核心试玩、完整局版本。所有准备完成后一次写入工作流；任何一步失败都不替换旧成果。
- 新成果先待确认，不由模型或生成检查替用户批准。确认整套修改后才更新相应阶段的确认记录。历史恢复核查所有关联快照，保留恢复前整套记录。
- 不增加依赖、数据库或云服务；不进入 2-10 导出节点。

## 验收与边界

用户验证：改衣服但发型不变、动作中的衣服同步、游戏玩法保持；背景修改不影响人物；取消不调用 AI；失败保留旧版；恢复和重开后各阶段外观与确认一致。助手仅做类型检查、启动所需构建和源码检查，真实图片效果与游戏体验待用户验收。
