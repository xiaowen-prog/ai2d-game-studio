## 请核对的需求

| 项目 | 本轮整理的产品要求 |
| --- | --- |
| 服务谁 | 不会写代码、但有游戏想法的个人创作者；包括游戏爱好者、策划和美术背景的人 |
| 解决什么问题 | 不会写代码，也能让 AI 把想法做成小型可玩游戏；做偏时能在中间修改，不用等整款完成 |
| AI 核心 | AI 生成角色、场景及玩法，并能根据自然语言持续修改；不能退化成固定模板或单纯调数值 |
| 首版游戏类型 | 支持2D横版闯关和俯视打怪，题材不限 |
| 完整使用过程 | 一句话需求 → 方向 → 人物及动作 → 场景 → 核心试玩 → 完整游戏 → 检查交付 |
| 用户控制 | 每一步看真实成果后确认或修改；未确认不做后续；可返回修改、恢复旧版、关闭后继续 |
| 首发与交付 | 沿用 macOS 本地桌面；交付可玩的小游戏、工程与网页游戏包；公网分享链接后置 |
| 暂不做 | 3D、多人联机、开放世界、大型商业游戏、复杂旧工程改造、用户自行配置 Agent |

首版规模沿用 PRD 建议：横版最多 3 个短关卡；俯视 1 张地图、2 类敌人、最多 2 种攻击、3 项升级和 3 波敌人；每个项目 1 个主角、1 套美术风格。超出范围先说明并由用户决定缩小，不默默删需求。

## 怎么判断产品真的做成

1. AI 能根据描述制作实际成果，用户提出的新要求能在游戏里生效，例如二段跳或剑气反弹。
2. 人物、场景和玩法分别确认，后续沿用用户确认的版本；AI 不能替用户确认。
3. 核心试玩可以亲自操作；最终能完整玩一局，并正常胜负、暂停和重开。
4. 修改失败不损坏旧成果，恢复旧版和关闭重开都保留一致的内容与确认记录。
5. 导出文件确实能运行；横版和俯视各有一个真实完整案例。
6. 在账户与环境就绪后，小白无需写代码即可完成制作、修改和恢复。

详细验收沿用 PRD A01–A12。真实 AI、图片、游戏效果与离线检查分别记录；审美和手感由用户实际体验，不承诺未经验证的成功率、速度或复用比例。

## 已发现的矛盾与处理

- **两套“阶段”容易混淆。**我们的开发阶段 0 是核对需求、阶段 1 是技术方案，之后才逐节点开发；产品里的方向、人物、场景是未来用户制作游戏的步骤。需求里包含完整游戏，不授权在一个开发阶段把全流程一次做完。
- **旧文档仍写“已通过”“继续 2-1”。**本轮项目状态及验收记录已重新整理；旧记录归档供追溯，旧技术方案与代码保留冻结，不用于跳阶段。
- **费用限制不能取消阶段验收。**当前节点未完成真实验证时如实待验，不能把其余功能塞进同一节点继续做。
- **手册默认网页/云部署，本项目已有桌面基础。**按用户的 Noobi.ai 二开目标处理，不自动新增网页后端、云账户或付费资源；具体技术复用到阶段 1 再判断。无需修改共享手册。

已对账：密钥保护、保存恢复、人工确认及真实验证底线无冲突；网页/云平台默认值不适用于本轮本地桌面范围。
