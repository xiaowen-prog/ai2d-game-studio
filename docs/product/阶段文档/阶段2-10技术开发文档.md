# 2-10 游戏交付

**把最后确认的游戏带走：可编辑的 Godot 工程、网页游戏、打开说明，以及一个便于保存的压缩包。**

用户“往下做”授权进入 2-10，不据此追加 2-9 效果验收通过。沿用已读开发 Skill、规则卡及通用手册第二、三部分，已对账；后续验收由用户进行。本轮不运行模型、图片、试玩、自动测试或最终 Skill 自检，只开发并做启动所需构建。

## 用户怎么用

1. 确认完整游戏后停在当前页面；点击“导出工程与网页游戏”才开始导出。
2. 导出直接使用已确认快照，不让 AI 修改游戏，不要求模型登录或再次生成素材。
3. 交付页预览实际导出的网页文件，显示对应游戏版本、导出时间与文件位置，可打开交付文件夹。
4. 文件夹包含 `godot-project/`、`web-game/`、中文说明、本机网页启动脚本和 `game-package.zip`。用户分别打开工程与网页游戏，确认一致后再确认交付。
5. 返回修改完整游戏不会自动调用 AI。游戏修改后旧导出包保留，新导出另存；旧包明确标为需要更新。

## 实现

- 复用版本快照、SHA-256 文件校验、桌面受控接口及本地预览服务。交付步骤改为宿主确定性导出，不进入 Codex 规划、制作或审查循环。
- 导出只读当前已确认完整游戏及其确认链；人物外观整套修改未确认、前置阶段过期时不能导出。
- 从快照清单选择工程资源和已有 Godot Web 构建。复制后逐文件核对与原快照一致，并检查基础入口及资源引用；不重建另一款游戏。过滤会话、日志、缓存、凭据及内部检查资料。
- 临时目录准备，全部成功后原子改名；每次导出独立目录，重复点击由现有操作标识控制。失败或停止保留旧成果与旧导出。
- 交付清单记录来源成果、来源快照、文件摘要；查看交付页与打开目录时核对清单和文件。内嵌预览直接读取交付包，关闭原图覆盖，避免拿工作区预览冒充导出结果。
- 网页游戏附带 Python 3 本地服务脚本，仅监听本机空闲端口，带 Godot 网页所需响应头；用户双击启动。压缩使用 macOS 现有 zip 工具，不新增依赖。

## 首版边界与验收

只交付本机文件，不做公网分享、云部署、平台安装包或签名。网页包不能简单双击 HTML 运行，说明中给出启动方法与 Python 3 依赖。Godot 工程使用 Godot 4 打开。

用户检查：未确认不能导出；导出不调用 AI；包内网页可玩、工程可打开；人物、玩法与最后确认版本一致；旧包不会被覆盖；关闭重开后能找到交付记录；修改后需要重新导出。本轮助手不打开游戏或声称实际运行通过。
