# 阶段 3-1：正式制作台界面

**解决的问题：把已确认的 Spline 设计接到真实制作流程，让用户先看成果，再确认或告诉 AI 怎么改。当前开发已交，业务验收交给用户；停在 3-1。**

## 授权与范围

- 用户在 3-0 Spline 预览交付后回复“可以继续推进吧”，据此登记设计确认，进入 3-1。
- 沿用开发 Skill、工作区规则、前端手册和技术路线，复用 React / Electron / Godot / 原有创作服务；无新增依赖、云服务或付费调用。
- 用户要求自己验收，因此未运行自动业务测试、模型冒烟、试玩及 `kit.sh 自检`。仅做类型检查与生产构建；用 `kit.sh 回到` 校正到用户已授权的 3-1，再领取任务。没有手改流程管家文件，没有调用“通过”。
- 已对账：数据、确认点与权限底线无冲突；验收执行人和桌面范围按用户最新要求适配。

## 本轮实现

| 页面 / 问题 | 本轮结果 |
| --- | --- |
| 首页 | 一句话描述入口、两种游戏方向、登录引导、近期项目；两侧已有角色素材仅作装饰，不充当用户成果 |
| 制作台 | 顶部阶段进度、左侧大幅真实成果、右侧 AI 创作搭档；人物动作仍在人物阶段内 |
| 核心操作 | 原有候选选择、确认、制作动作、继续制作、停止、失败重试、局部外观修改、整套恢复、导出和打开文件夹全部接原接口 |
| 草稿 | 各阶段分别保存输入，切换不清空，兼容旧项目草稿；Enter 发送、Shift+Enter 换行、中文选字保护沿用原逻辑 |
| 等待 / 失败 | 展示真实状态，不伪造百分比；已有画面保留，错误给出账户与环境入口；预览失败可单独重新读取 |
| 打开项目 | 先显示读取进度；读取失败可重试，不误落入旧的通用开发页面 |
| 历史与修改影响 | 从画面下方打开历史；恢复或影响前后阶段的修改先弹窗说明；复用已有可用键盘操作的 Modal |
| 窄窗口 | 800px 以下对话移到成果下方，进度横向滚动；版本入口、确认和修改保留 |
| 外观 | 黑底、透明面板、蓝色主按钮，保留原有浅色切换；没有替换或删除旧版项目支持 |

## 维护位置

正式源码在 `Noobi.ai/src/renderer/`：`App.tsx`、`components/CreationWorkspace.tsx`、`components/HomeDashboard.tsx`、`components/RotatingIdeaInput.tsx`、`components/creation.css`、`studio.css`、`main.tsx`、两张复用的首页装饰图。首页输入示例限定已支持的 2D 玩法，不再轮播原平台的 3D、赛车与多人示例。

没有修改本轮以外的主进程、工作流协议或生成器；既有 2-6 至 2-10 未提交变更完整保留。确认仍绑定成果版本和记录版本，后端继续处理重复动作、影响确认、审查与历史恢复。界面没有增加第二套保存或生成服务。

## 交付与边界

双击项目根目录 `打开3-1正式制作台.command`，选择横版或俯视，点已有项目卡片。复用前面节点的续做入口；首次使用入口时会准备已保存样例的独立副本，不覆盖原样例。正常打开不会自动制作。

本次工程构建通过；窗口展示只用于交付画面，不代表功能或 AI 效果已验收。未自动输入修改、确认、恢复、导出或操作游戏。3-2 安装包与后续上线未开始。
