## 1. 页面怎么组织

| 区域 | 用户看到什么 | 解决的问题 |
| --- | --- | --- |
| 顶部步骤 | 方向、人物、场景、核心试玩、完整游戏、交付；标出当前和已确认步骤 | 知道做到哪一步 |
| 中间成果 | 当前人物、场景或游戏占据主要空间；先结果，后简短说明 | 不必先读大段文字 |
| 右侧 AI 对话 | 简短成果说明、明确的确认按钮、带修改例子的输入框 | 知道下一步点什么 |
| 版本入口 | 统一保留版本记录与整套恢复影响说明 | 修改不满意时能退回 |
| 顶部状态 | 与当前创作阶段一致的状态；历史内容明确区分 | 不把旧成果误当成最新结果 |

首次使用提示放在创作入口附近，登录回来保留想法。等待时保留已有成果，用真实阶段描述进展。失败时说明哪一步失败、保留了什么，并给重试和恢复入口。

## 2. 确认与修改

沿用当前主进程的真实阶段规则，按钮文案明确说明是否启动下一步：方向确认后制作人物；人物候选先保存，再手动制作动作；动作确认后制作场景；场景确认后开始核心试玩；核心试玩和完整游戏确认后先保存，由用户另行开始完整局或导出。

确认绑定当前版本。修改影响前置成果时先展示影响。完整游戏继续保留“玩法与难度／只改人物外观／只改背景”。恢复的是整套状态。交付继续要求用户实际打开与验收，不由前端代为通过。

Enter 发送，Shift + Enter 换行；中文输入法选字时不误发送。任务进行时禁止重复提交。关闭或重开不重复生成，真实状态由主进程提供。

## 4. 状态呈现

| 实际状态 | 面向用户的呈现 |
| --- | --- |
| idle | 当前步骤还未开始，说明会产出什么 |
| running | 正在制作哪一步，上一版仍保留，可停止；不伪造进度百分比 |
| awaiting-confirmation | 待你确认，给本版成果和明确的下一步 |
| confirmed | 已确认并保存；根据阶段提供下一步入口 |
| needs-update | 前面已变化，当前成果需要更新；不能沿用旧确认 |
| failed / stopped | 修改未完成／已停止，说明已有成果和继续方法 |
| 页面读取失败或状态过期 | 先重新读取原任务，不直接重发制作请求 |
| completed | 交付已由用户确认，仍可返回修改 |

## 5. 视觉与尺寸

具体值见 [Spline 采用说明](../设计参考/Spline-采用说明.md)。黑色背景、半透明面板、单个蓝色主操作；24px 卡片与 12px 按钮圆角。字体以 400/500 为主，中文使用系统字体。画面占据主要区域，缩短文字说明。

桌面使用顶部步骤、中间成果、右侧 AI 对话。窄窗口把对话移到成果下方；顶部步骤可横向滚动，版本入口仍可见。正式桌面目标沿用最小 760×620，常用 1280 与 1440 宽度；不新增手机产品承诺。本轮没有进行这些尺寸的业务验收。
