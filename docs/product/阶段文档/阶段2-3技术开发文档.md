# 阶段 2-3｜让选中的人物动起来

**本节点只完成：AI 制作人物动作 → 真实预览 → 描述修改 → 确认和恢复。完成后停在人物，不开放场景。**

用户在底座审查及修复后明确“开始做吧”，恢复本节点。2-1、2-2 已验收，不重新制作其功能。

## 复用与新增

复用 Noobi 的 Codex 规划／制作／审查、参考原图生成、素材凭证、Godot 检查与网页导出、桌面预览，以及已有阶段保存和历史恢复。新增选中人物的动作清单、动作制作入口、操作说明、修改／确认入口、当前导出人物实际按键与动画帧检查。无新依赖、服务商或付费 API。

## 用户怎么用

1. 选好人物并确认，点击“制作人物动作”。不会因打开项目或选择人物自动生成。
2. AI 沿用选中人物：横版制作待机／走路／跳跃；俯视制作待机／走路／攻击。显示原人物对照、真实动作预览和按键说明。
3. 输入“走路慢一点，外观不变”等修改，重新查看。仅调速度复用已有图集；改姿态才生成新图。
4. 点击“确认人物动作并保存”。保持在 2-3，不自动进入场景。
5. 恢复历史版本无需生成。若要换脸、换衣或换人物，先“返回修改人物形象”，说明旧动作需要重做；原动作版本仍可恢复。

## 实现与检查

- 主进程控制候选／动作子状态、确认版本与任务；旧 2-2 存档兼容。
- 候选图不可被动作生成覆盖。AI 用参考原图制作透明动作图集，生成 Godot SpriteFrames 与最小预览工程。
- 程序核对当前任务、原人物摘要、图片来源凭证、图集尺寸、真实姿态变化、资源绑定和帧率。
- 复用原引擎检查后，在实际导出工程注入固定按键，验证移动、主动作、不同帧播放及回到待机；当前宿主结果再交给 AI 审查。旧报告归档，不充当本轮证据。
- 失败保留上版，不自动重画。界面提示重试或恢复；保存与恢复不调用模型。

## 验收标准

| 维度 | 通过标准 |
| --- | --- |
| 人物继承 | 两个候选原图摘要不变；动作中发型、衣服、武器和视角与选中人物一致 |
| 真正动作 | 横版待机／移动／跳跃，俯视待机／移动／攻击；实际引擎按键触发且不同姿态帧播放 |
| 持续修改 | “走路慢一点”仅降低播放速度，复用图集且不改变其他动作；需重新确认 |
| 失败保护 | 空帧、静态复制、版本不匹配、资源未接入或引擎失败均不能覆盖原成果 |
| 用户交互 | 能看原人物和动作、按键操作、发送修改、确认、恢复；首次未登录有原有指引 |
| 保存与边界 | 关闭重开仍是同一版本；恢复无新调用；场景保持未开始 |

## 验证计划与费用

先离线测试、真实 Godot 工程检查，再用现有 ChatGPT Pro 做真实生成。工程测试图只用于验证检查器，不能冒充 AI 成品。真实样例计划：复用已验收俯视人物做动作和速度修改；补一个横版人物样例做跳跃。初次计划总计 12 次文字、4 次图片；发现尺寸与来源证明衔接问题后，复用已生成素材做修复复验，每轮文字最多 6 次、俯视新增图片 0 次、横版新增动作图最多 1 次。验收脚本等待错误导致提前停止的一轮也计入实际消耗；最终总数以自动汇总为准。不自动重画，不使用付费 API、充值或新服务。遇到失败先查原因，不循环消耗。

结果分开记录程序检查、真实调用、图片外观与真实界面，完成后执行 Skill 自检，等待用户验收，不执行阶段通过。

两个真实视角及一次速度修改通过；最终 436/436 与六项 Skill 自检通过，流程状态为“等验收”。实际消耗 23 次文字、4 次图片，所有失败和复验均保留。详见 [验收报告](../evidence/阶段2-3/验收报告.md)。本节点停止，不进入场景。
