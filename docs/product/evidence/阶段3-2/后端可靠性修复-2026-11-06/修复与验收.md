# 造境：后端可靠性修复与验收

2026-11-06。当前仍是 3-2；本次交付源码和本机构建，不登记产品验收通过，不发布、不重新打包旧 DMG。

## 结论与参考来源

按用户提供的审计逐项核实，在原 Electron / TypeScript / Codex App Server 上修复实际缺口。没有换后端、增加 Python 服务、数据库或新依赖。

参考老师的 [Personal-Agent](https://github.com/hubooooooo/Personal-Agent)，使用本机已有快照 `de09b4ab769f75740139bbc5d336bd6e5e29c0e3`；未声称这是远端最新版本。本次独立编写 TypeScript 实现，借鉴：

- `app/agent/context_assembler.py`：不同来源的上下文分预算，保留当前权威约束。
- `app/agent/tool_registry.py`：执行前校验、截止时间、区分执行失败与结果观察失败。
- `app/agent/memory/summary.py`：按对象去重、后台调度、退出清理和异常隔离。

审计引用的 `s04_hooks`、`s08_context_compact`、`s10_task_system`、`s11_background_tasks` 不是该仓库快照的实际目录，故按上述真实模块适配，不虚构移植来源。

## 审计校正与改动

| 项目 | 核实结果与修复 |
| --- | --- |
| 没有模型 SDK，所以可能不是 Agent | 结论不成立。现有后端通过 Codex App Server 的线程与回合运行 Agent；保留原链路。 |
| 上下文压缩 | [官方 App Server 文档](https://learn.chatgpt.com/docs/app-server) 已提供压缩方法和事件。宿主现在接入 `contextCompaction` 开始/完成及旧 `thread/compacted` 通知；跨角色参考输出限制为 12,000 字符，宿主证据按条限制，过长时标明省略和总数。当前节点任务、角色权限、确认规则不截断。没有另外调用模型做摘要，也没有声称实测了自动压缩。 |
| 工具钩子 | 新增宿主素材工具的执行前拦截和执行后观察。前置检查 3 秒超时即拒绝；校验当前活跃线程、当前步骤工具白名单和本地检查模式。观察异常不改变真实工具结果。日志只记录工具名、状态和耗时；来源证明等关键校验仍会阻断。范围是宿主动态工具，Codex 自带 shell/MCP 仍由其沙箱与审批机制管理。 |
| 任务持久化 | 保留原固定阶段依赖和确认模型，文件格式不变。增加同进程多个 Store 实例按文件排队；写临时文件、同步文件后原子替换。Electron 原有单实例锁仍生效；这不是多机数据库锁。同步或异步 UI 通知异常不会让已保存任务卡住。 |
| 后台素材重试 | 审计只看到 IPC 入队，漏掉旧前端随后调用 `runProject`。现改为后端一次接管入队和原有“生成＋接入”流程，前端只发一次请求。同一项目去重，重试队列一次运行一个项目，最多保留 20 个项目；单任务 30 分钟后发出停止信号。队列不自动重跑失败任务，原 Agent 内部已有审查/修复上限未更改。 |
| 停止与退出 | 重试的停止信号传到素材 API；已停止请求不再进入文件保存。即使执行器未及时响应停止，也等写入任务真正结束才释放项目占用。停止、超时、失败会保留状态；重启将未完成的 queued/generating 工单标成中断，不自动再次调用服务。远端可能已经处理取消请求，不能把取消当作退款或未计费证明。 |
| 技能加载 | `skill` 输入项是交给 Codex 运行时的技能引用，宿主没有读取整篇 Skill 后拼入 prompt；不能仅据名称/路径参数就断言整篇注入。仍按当前制作能力选择工具和图片技能，没有重复实现另一套技能检索服务。 |
| 通用 DAG、定时任务、Agent 团队 | 当前产品是固定阶段、单写入者。没有为审计分类补无需求的通用 DAG、定时器或并行写同一工程，避免破坏确认与版本继承。 |
| 验收、成功率、耗时与费用、Windows/多人/公网 | 属于待用户实测或原 P1 范围，不能通过改代码填成已通过；本次不扩展这些功能。 |

分阶段项目继续从当前步骤发起修改，不能从旧素材重试入口越过确认。旧的非分阶段项目保留独立素材重试；后台仍使用原制作与接入链路，不把“生成了文件”当成“已经接入”。

## 用户照着验收

先正常退出旧制作台及旧本机网页服务，再双击项目根目录的 `打开3-2本机网页版.command`，选择横版或俯视。它使用本次已构建的源码和原续做数据；不要用旧 DMG 验证本次修复。

| 顺序 | 点哪里、做什么 | 通过标准 |
| --- | --- | --- |
| 1 | 打开原项目，再打开历史版本列表 | 原项目、已确认步骤、旧版本仍在；仅打开页面不自动生成。 |
| 2 | 在当前步骤输入一次修改并发送 | 只启动一次；出现结果后停在待确认，不自行进入下一步骤。实际修改质量由用户判断。 |
| 3 | 制作过程中关闭页面，再重新打开同一入口 | 后端仍运行时可重新读到状态；界面连接中断不会让后台凭空多启动一次。关闭整个应用后重开则显示中断，不自动重做。 |
| 4 | 制作中点击停止，再查看已有成果 | 不把停止显示成成功，不继续下一步；已有确认成果和历史保留。远端正在执行的调用可能仍收费。 |
| 5 | 按原流程打开历史并选择恢复；确认影响后恢复 | 恢复的成果、步骤和确认状态一致，没有丢掉旧版本。 |
| 6 | 到交付步骤，点击导出 | 沿用原流程导出并另存；真实打开、游戏效果仍由用户验收。 |

旧的非分阶段项目单独在桌面源码版的素材区点“重新生成/重新接入”，检查一次点击自动进入后台任务；重复点击不产生第二个同项目任务；失败有记录，重开不自动重复付费。这个入口不属于当前分阶段网页的修改按钮，不能用它绕过已确认步骤。

用户需要实际发起生成/修改才会发生真实模型和素材调用，费用仍按原账户或供应商计费。本次没有实测新增费用、耗时或成功率，不能承诺零成本或已达到业务指标。
