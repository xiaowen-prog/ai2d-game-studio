# 2-9 验收：只换外观，保留玩法，整套恢复

**重点看：衣服改了但发型与玩法不变；不满意时，整套恢复原版。**以下是验收标准，尚非实测结果。

## 从哪里开始

1. 双击项目根目录 `打开2-9制作台.command`，选择横版或俯视。入口沿用 2-7 / 2-8 的续做工作区，不另建空项目，也不自动生成。
2. 打开已有项目，先确认当前完整游戏。如果还停在核心试玩，按 2-7 / 2-8 的清单，由你点击制作完整小局并确认；助手没有提前制作新样例。
3. 在完整游戏底部，“这次改什么”选择“只改人物外观，保留玩法”，输入“只把衣服改成白色，发型、武器、动作和玩法保持不变”（如果已是白衣，可改成另一种颜色）。
4. 先查看影响提示。点“先不改”应保持原样；点“确认影响，继续”才调用 AI。
5. 完成后展开“修改前 / 修改后”图片，查看人物原图和动作图集，再查看游戏预览。可点左侧人物、场景、核心试玩检查同步结果；回到完整游戏后点“确认整套外观修改并保存”。
6. 点“恢复外观修改前整套版本”，查看弹窗并确认。原人物、背景、玩法和确认状态应一起恢复。还可以从历史选回较新的“已确认整套外观修改”。

背景修改同理：确认完整游戏后选“只改背景，保留玩法”，描述新的背景主题。首版保持原视角、尺寸和布局；不借此新增地形、换角色、换动作或改变玩法。

## 验收维度与指标

| 维度 | 操作 | 通过标准 |
| --- | --- | --- |
| 修改前说明 | 选人物外观并发送，先不确认 | 明确说明会同步人物和动作、影响哪些阶段、玩法保持；尚未开始生成 |
| 取消 | 点“先不改” | 图片、游戏、确认状态均不变，输入要求仍保留 |
| AI 外观修改 | 发起衣服颜色修改 | 原图与动作图集均有真实变化，不是只改文案或给整个人物套颜色 |
| 局部保持 | 对照修改前后，并看各动作 | 发型、脸、武器与非指定部分保持；所有动作中衣服一致，没有残留旧色、错位或剪断 |
| 玩法保持 | 修改前后用相同操作 | 横版的跳跃次数、地图、物品数和倒计时保持；俯视的剑气反弹、三波数量、升级和生命规则保持；暂停、重来、音效仍正常 |
| 跨阶段同步 | 查看人物、场景、核心试玩、完整游戏 | 被修改的外观在对应预览里一致；不出现原图新衣、试玩旧衣的混用 |
| 人工确认 | 生成后查看状态，再确认整套 | 相关阶段先待确认；点击整套确认后一起变为已确认，不自动导出 |
| 背景修改 | 选背景并修改主题 | 人物原图和动作保持，背景同步至场景、试玩和游戏；实际碰撞位置、规则及操作保持 |
| 失败或停止 | 生成中点停止，或发生错误时观察 | 保留旧成果；可恢复修改前整套版本；重试仍沿用原修改范围，没有假成功 |
| 整套恢复 | 恢复修改前版本，再选回新版本 | 图片、游戏规则、所选人物和确认记录随版本一起切换；两边版本均保留；恢复不重新生成 |
| 重开 | 在待确认和已确认状态分别关闭再打开 | 成果、状态与历史保留；中断任务显示已停止，不自动重试或自动确认 |
| 其他跨阶段修改 | 返回修改方向或其他早期内容，先看影响提示 | 明确提示哪些后续阶段需更新；保留的旧成果显示“需要更新”，不能直接当作最新确认版 |

若出现玩法被改、发型被改、动作未同步、只恢复图片却没有恢复确认记录，判本节点不通过。请记录“操作 + 预期 + 实际”，保留当前项目以便修复。

真实生成由你点击触发，使用已有 Codex 图片编辑能力。人物任务要求编辑原图与动作图集两张，背景任务一张；不自动重画、不接入新的付费图片服务。用户看到的实际效果仍需人工判断。
