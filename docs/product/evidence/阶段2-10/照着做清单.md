# 2-10：把确认的游戏带走

**本次验收：导出的工程能继续编辑，网页游戏能玩，而且与最后确认的版本一致。由你操作验收。**

## 从哪里打开

双击项目根目录 `打开2-10制作台.command`，输入 `1` 打开原横版项目，输入 `2` 打开原俯视项目。如果原窗口还开着，先正常退出，再用新入口打开。

沿用之前的续做区，不另外新建空项目。两种游戏各验收一次。如果还没有完整小局，请先按 2-7 / 2-8 清单制作并确认；如果 2-9 外观修改还待确认，请先确认整套修改或恢复旧版。

## 正常流程：全部满足才通过

| 步骤 | 操作 | 通过标准 |
| --- | --- | --- |
| 1. 先确认 | 确认完整游戏 | 保存后仍停在完整游戏；不自动导出，不再自动制作 |
| 2. 开始导出 | 点击“导出工程与网页游戏” | 进入交付页；不新增模型或图片调用，未登录模型也不阻断导出 |
| 3. 找到文件 | 完成后点击“打开交付文件夹” | 有 `godot-project/`、`web-game/`、`打开说明.md`、`打开网页游戏.command`、`serve-game.py`、`delivery-manifest.json`、`game-package.zip`，缺一不通过 |
| 4. 网页运行 | 双击包内“打开网页游戏.command” | 浏览器打开本机游戏；能开始、操作、暂停、重来，并完成一局；不是双击 HTML |
| 5. 核对版本 | 对照制作台最后确认的游戏 | 人物、衣服、背景、玩法和本局难度一致。制作台交付页也读取这一包的网页文件，不显示工作副本冒充导出结果 |
| 6. 工程可编辑 | 用 Godot 4 导入 `godot-project/project.godot`，等导入结束后运行 | 没有缺资源或脚本错误；能运行同一款游戏，工程里能找到人物、场景和脚本 |
| 7. 压缩包可带走 | 把 `game-package.zip` 复制到另一个位置，解压后按步骤 4、6 打开 | 两种文件都能独立打开，不依赖原制作台项目目录或模型登录 |
| 8. 记录完成 | 点击“我已验收，确认交付”，退出并重新打开制作台 | 仍显示同一份交付、对应游戏版本和已确认状态，能再次打开文件夹 |

网页启动脚本需要 Python 3；工程需要 Godot 4。启动后保留终端窗口，结束时按 Ctrl+C。网页地址仅供本机访问，本节点不提供公网链接或应用安装包。

## 修改与异常：逐项记结果

| 操作 | 通过标准 |
| --- | --- |
| 返回完整游戏，只查看不输入修改 | 不调用 AI；原交付包仍保留 |
| 修改游戏并确认，再次导出 | 新包保存到另一个目录；旧包不覆盖，两个包分别对应各自版本。修改游戏本身才会使用 AI |
| 在外观修改等待整套确认时尝试导出 | 不能跳过确认导出；不丢草稿 |
| 导出过程中停止（来得及点击时） | 不把半成品标记完成；原游戏和旧包还在，可以重新导出 |
| 临时把交付包内 `web-game/index.html` 改名，重新打开交付页 | 明确提示文件缺失或变化；不能继续确认该包，可重新导出。验证后把原文件名改回 |
| 核对 ZIP 和文件夹内容 | 不包含制作会话、账户文件、内部审查记录和缓存；游戏素材与中文说明齐全 |
